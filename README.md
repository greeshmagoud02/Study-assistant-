# Study Assistant

Turn raw study notes — or just a topic name — into interactive flashcards and quizzes, generated by Claude and rendered as real React UI (not a chatbot transcript).

> Paste your notes → pick "Generate Flashcards" or "Generate Quiz" → Claude returns structured JSON → the app renders fully interactive components: flip cards, shuffle, take the quiz, get scored, review explanations, retry only what you got wrong.

## Overview

Study Assistant is a full-stack SaaS-style application:

1. The user pastes notes or types a topic on the **Home** page.
2. The React client calls the **Express backend** (`POST /api/generate`).
3. The backend calls **Claude** with a strict system prompt that forces raw JSON output only.
4. The backend **validates** the AI response with **Zod** before ever sending it to the client.
5. The client parses the validated JSON and renders it as **interactive React components** — flashcards or a quiz — never as raw text or chat bubbles.

The AI is used purely as a **structured content generator**, not as a conversational interface.

## Features

### Flashcards
- Flip animation (3D card flip, click or Space)
- Previous / Next navigation
- Shuffle deck
- Restart deck (resets order + progress)
- Progress indicator + viewed-card count
- Download the flashcard set as JSON

### Quiz
- Radio-button single-choice questions
- Previous / Next navigation, next disabled until answered
- Submit (disabled until every question is answered)
- Score summary with percentage
- Full review: correct answer, your answer, and an explanation per question
- **Retry only incorrect questions** — spins up a new round containing just the questions you missed
- Quiz timer
- Client-side difficulty badge (heuristic, not fabricated AI output)
- Download the quiz as JSON

### Core UX
- Large textarea with live character counter, min/max length enforcement
- Loading states: skeleton UI + disabled buttons + inline spinner, tailored per mode
- Empty state with icon + helpful copy
- Error state with a human-readable message and a **Retry** button
- **Race-condition safe**: every new "Generate" click aborts the previous in-flight request via `AbortController` — only the newest response can ever land
- Dark mode (system-aware default, manual toggle, persisted)
- Keyboard shortcuts inside flashcards: `Space` flip, `←/→` navigate, `S` shuffle, `R` restart
- Copy notes to clipboard
- Recent history (last 10 generations) saved to `localStorage`, click to instantly reload without another API call
- Fully responsive, mobile-first layout

## Tech Stack

**Frontend:** React 18, Vite, JavaScript, Tailwind CSS, Axios
**Backend:** Node.js, Express.js, Anthropic Claude API (`@anthropic-ai/sdk`)
**Validation:** Zod (both request and AI-response validation)
**Deployment:** Vercel (frontend), Render (backend)
**Version Control:** Git, GitHub

## Installation

```bash
git clone https://github.com/<your-username>/study-assistant.git
cd study-assistant

# Backend
cd server
npm install
cp .env.example .env   # then fill in ANTHROPIC_API_KEY

# Frontend
cd ../client
npm install
cp .env.example .env   # defaults to http://localhost:5000, fine for local dev
```

## Environment Variables

### `server/.env`

| Variable | Required | Description |
|---|---|---|
| `ANTHROPIC_API_KEY` | Yes | Your Anthropic API key. Never committed — server only. |
| `CLAUDE_MODEL` | No (default `claude-sonnet-5`) | Claude model id to use. |
| `PORT` | No (default `5000`) | Port the Express server listens on. |
| `CLIENT_ORIGIN` | Yes in production | Comma-separated list of allowed CORS origins, e.g. your Vercel URL. |
| `NODE_ENV` | No | `development` or `production`. |

### `client/.env`

| Variable | Required | Description |
|---|---|---|
| `VITE_API_URL` | Yes | Base URL of the deployed Express backend, no trailing slash. |

Both `.env.example` files are committed; the real `.env` files are gitignored and **never** contain keys in version control.

## Architecture

```
┌──────────────┐      POST /api/generate       ┌──────────────────┐      messages.create      ┌──────────────┐
│  React (Vite)│ ─────────────────────────────▶ │  Express server  │ ─────────────────────────▶ │  Claude API  │
│  Home page   │ ◀───────────────────────────── │  Zod-validated   │ ◀───────────────────────── │              │
└──────────────┘   { success, data } | error     └──────────────────┘      raw text (JSON)       └──────────────┘
```

- **Client → Server**: `text` + `mode` (`flashcards` | `quiz`), request validated with Zod before it ever reaches Claude.
- **Server → Claude**: a mode-specific system prompt (see [`server/prompts/systemPrompt.js`](server/prompts/systemPrompt.js)) that mandates raw-JSON-only output.
- **Claude → Server**: raw text response. Stripped of any accidental markdown fences, parsed as JSON, then validated against a strict Zod schema (`flashcardsResponseSchema` / `quizResponseSchema`). Anything that doesn't match — missing fields, wrong types, empty arrays, mismatched `correctAnswer` — is rejected with a `502 SCHEMA_MISMATCH` before it reaches the client.
- **Server → Client**: `{ success: true, data }` on success, or `{ success: false, error: { code, message } }` on any failure, always with an appropriate HTTP status.
- **Client rendering**: the validated JSON is handed to `FlashcardDeck` or `QuizContainer` — dedicated React components with their own local state (current index, flip state, answers, timer) — never dumped as raw text.

### Race-condition handling

`useGenerate` keeps a single `AbortController` in a ref. Every call to `generate()` aborts whatever request is currently in flight before starting a new one, and the abort signal is checked again before committing the response to state. So mashing "Generate Quiz" five times in a row is safe — only the last click's response can ever be rendered.

## AI Usage

Claude is used **exclusively** as a structured-data generator, never as a conversational agent:

- The system prompt (`server/prompts/systemPrompt.js`) explicitly forbids markdown fences, commentary, and partial JSON, and pins the exact schema shape for each mode.
- The server treats the model's text output as an opaque string that must survive `extractJson()` (strips stray fences/whitespace) and then a Zod `safeParse()`. If either step fails, the request fails cleanly with a typed error — the model's raw text is never forwarded to the client.
- No conversation history is kept or sent; each request is a single independent generation call.

## Deployment

### Backend → Render

1. Push this repo to GitHub.
2. In Render: **New → Web Service**, connect the repo.
3. Render will read [`render.yaml`](render.yaml) automatically (Blueprint), or configure manually:
   - Root directory: `server`
   - Build command: `npm install`
   - Start command: `npm start`
   - Health check path: `/health`
4. Set environment variables in the Render dashboard: `ANTHROPIC_API_KEY`, `CLIENT_ORIGIN` (your Vercel URL, added after step below), `CLAUDE_MODEL`.
5. Deploy. Note the public URL, e.g. `https://study-assistant-server.onrender.com`.

### Frontend → Vercel

1. In Vercel: **New Project**, import the repo.
2. Set **Root Directory** to `client`.
3. Vercel auto-detects Vite via [`client/vercel.json`](client/vercel.json) (build command `npm run build`, output `dist`).
4. Set environment variable `VITE_API_URL` to your Render backend URL from above.
5. Deploy. Note the public URL, e.g. `https://study-assistant.vercel.app`.
6. Go back to Render and set `CLIENT_ORIGIN` to that Vercel URL so CORS allows it, then redeploy the backend.

No code changes are required to deploy — only environment variables.

## Known Limitations

- Render's free tier spins down on inactivity — the first request after idle can take 30–60s (a `504`/timeout on that first call is expected; retry succeeds).
- History and theme are stored in `localStorage`, so they're per-browser, not synced across devices — there's no user accounts/auth layer.
- Very long notes (near the 12,000-character limit) may cause Claude to trim the number of generated items to stay within the response token budget.
- No automated test suite (unit/e2e) is included yet — see Future Improvements.

## Future Improvements

- Automated tests: Vitest + React Testing Library on the client, Jest/Supertest on the server.
